# 独立评分架构

```text
MCP 客户端 -> mcp_server.py（标准库，stdio，固定管理员配置）
                   -> evaluate.py（新输出目录、输入/代码哈希、固定 v3 权重）
                          -> worker.py（每题独立进程）
                                 -> src/：validation 与六项适配指标
                                 -> vendor/cadgenbench/：精选几何和指标实现
                          -> aggregate + summary + report + comparison
CLI 用户 --------> evaluate.py
```

`mcp_server.py` 不导入几何依赖，不连接 Fusion，也不导入模型 CLI 或流水线。握手及工具目录可在禁用 site-packages 的解释器中运行；执行评分要求配置的子进程 Python 安装评分依赖。stdout 仅有 JSON-RPC，评分过程的文本输出进入任务日志。

服务只接受白名单目录中的三个输入文件。MCP 固定 v3、仓库权重与每任务单 worker；管理员控制总活动任务数和超时。服务计算并冻结输入哈希，原评测入口再次核验、复制输入、启动 worker，最终验证原始和暂存字节及代码未变。输入/结果身份失败会失去评分资格。

任务外层目录由随机 ID 创建；评测子目录不存在时才运行。服务进程记录 `queued → running → completed/failed`。普通断开会等待正在运行的有界任务结束；强杀/系统崩溃不提供恢复保证。会话索引不跨重启，持久证据仍可直接读取。

输入白名单并非操作系统沙箱，也不是 GT 保密的独立用户边界。服务按可信同账户使用设计，管理员必须负责配置与文件权限。进程隔离主要用于限制单题故障、超时及跨题缓存。

保留的 v2 CLI 代码用于明确选择历史协议；默认 CLI 与 MCP 均使用 v3。来源哈希清单只覆盖原样移植文件；新增服务、文档和启动器由发布版本管理，便携包清单再绑定实际分发字节。
